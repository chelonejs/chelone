A server field prints a record value the way its client twin does, with no
hook and no context, so it renders in a React Server Component. It ships in
the `@chelone/react/rsc` entry:

- `<ServerTextField>` prints what [TextField](/docs/viewing/text-field) prints.
- `<ServerNumberField>` prints what [NumberField](/docs/viewing/number-field) prints.
- `<ServerDateField>` prints what [DateField](/docs/viewing/date-field) prints.
- `<ServerUrlField>` renders what [UrlField](/docs/viewing/url-field) renders.
- `<ServerEmailField>` renders what [EmailField](/docs/viewing/email-field) renders.
- `<ServerFileField>` renders what [FileField](/docs/viewing/file-field) renders.
- `<ServerImageField>` renders what [ImageField](/docs/viewing/image-field) renders.
- `<ServerCurrencyField>` prints what [CurrencyField](/docs/viewing/currency-field) prints.
- `<ServerBooleanField>` renders what [BooleanField](/docs/viewing/boolean-field) renders.
- `<ServerSelectField>` prints what [SelectField](/docs/viewing/select-field) prints.
- `<ServerRatingField>` renders what [RatingField](/docs/viewing/rating-field) renders.

Each renders the same markup as its twin, and nothing when the value is empty
and `empty` is unset. The install command below adds the first seven: the link
fields bring the text, number and date fields with them. The last four are
their own item, `npx shadcn add @chelone/server-value-fields`.

## When to use one

Use a server field for a read-only page the server renders from data it
already holds, so the page ships no field code to the browser. Use the client
field inside `<Show>`, `<List>` or a `<DataTable>`, where the record comes from
context.

What a server field cannot do:

- It reads no record context, so `record` is required.
- It reads no i18n context. Pass `i18n` to translate `empty`; without it,
  `empty` prints as is.
- It takes no callback prop, so there is no `transform`. Shape the value
  before you pass the record.

## With TanStack Start

A server function reads the record and returns the rendered fields, and the
route renders what its loader got:

```tsx
import {
  ServerDateField,
  ServerNumberField,
  ServerTextField,
} from "@chelone/react/rsc";
import { createFileRoute } from "@tanstack/react-router";
import { createServerFn } from "@tanstack/react-start";
import { renderServerComponent } from "@tanstack/react-start/rsc";

const getPostFields = createServerFn().handler(async () => {
  const { data: post } = await dataProvider.getOne("posts", { id: 1 });
  return renderServerComponent(
    <>
      <ServerTextField record={post} source="title" />
      <ServerNumberField record={post} source="views" />
      <ServerDateField record={post} source="published_at" showTime />
    </>,
  );
});

export const Route = createFileRoute("/posts/1")({
  loader: () => getPostFields(),
  component: () => Route.useLoaderData(),
});
```

`source` is checked against the record's type, so a misspelled path is a type
error, as on the client fields.

## Links and images

The url, email, file and image fields put a stored value into an `href` or a
`src`. Each passes it through the same check as its client twin, in core, so a
stored `javascript:` url never becomes a live link on the server either:

- `<ServerUrlField>` prints a url it refuses as text, with no `<a>`. A value
  with no scheme must start with `/` or `#`, so `example.com` prints as text.
- `<ServerEmailField>` always puts the value behind `mailto:`.
- `<ServerFileField>` keeps the `<a>` of a url it refuses, with no `href`.
- `<ServerImageField>` keeps the `<img>` of a `src` it refuses, with no `src`.
  A raster `data:image` passes; an SVG one does not.

`target="_blank"` with no `rel` gets `rel="noopener noreferrer"` on the url and
file fields. For an array, `src` and `title` on the file and image fields name
the path on each item:

```tsx
<ServerFileField record={product} source="attachments" src="url" title="name" />
```

None takes `onClick`. The client twins stop click bubbling so a `DataTable`
row click does not fire, and a server list has no row click handler.

## Currency, boolean, select and rating

These four read through the same core functions as their twins, so a value
prints the same on the server:

- `<ServerCurrencyField>` takes `currency`, `displayLocale`, `storeAsMinorUnits`
  and `options`. With no `displayLocale`, the locale is the `i18n` locale, then
  the runtime's. A plain number with no `currency` throws, as `CurrencyField`
  does.
- `<ServerBooleanField>` takes `TrueIcon`, `FalseIcon`, `valueLabelTrue`,
  `valueLabelFalse` and `looseValue`. There is no tooltip, since that is a
  client component. The label is the icon's `title` and a visually hidden
  `<span>`, so a screen reader reads the state. Pass `i18n` to translate it;
  without `i18n` it is English.
- `<ServerSelectField>` takes `choices`, `optionValue`, `optionText` and
  `translateChoice`. `optionValue` and `optionText` are paths into a choice,
  checked against its type, and `optionText` takes no function.
- `<ServerRatingField>` takes `max`, `allowHalf` and `countSource`, and renders
  the same stars with `role="img"` and an `aria-label`.

```tsx
<ServerCurrencyField record={product} source="price" currency="USD" />
<ServerBooleanField record={post} source="published" i18n={i18n} />
<ServerSelectField record={post} source="status" choices={statuses} />
<ServerRatingField record={product} source="rating" allowHalf />
```
