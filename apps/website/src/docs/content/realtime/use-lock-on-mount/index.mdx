---
title: "useLockOnMount"
description: "Holds a record's lock while the component is mounted and reports the lock, whether it is being taken, and the last failure. Needs a realtime data provider with lock support."
---

`useLockOnMount` takes a lock when the component mounts and releases it when it
unmounts, including a lock still being requested. `<LockOnMount>` is the same
session with render props or slots around it.

## Signature

```ts
function useLockOnMount(options?: UseLockOnMountOptions): UseLockOnMountResult

interface UseLockOnMountOptions {
  /** Defaults to the resource context. */
  resource?: string;
  /** Defaults to the id of the record context. */
  id?: Identifier;
  /** Defaults to the auth provider's identity. */
  identity?: Identifier;
  meta?: Record<string, unknown>;
  /** Called with a failed lock or release. A new function every render never relocks. */
  onLockError?: (error: Error) => void;
}

interface UseLockOnMountResult {
  lock: Lock | null;
  isLocking: boolean;
  lockError: Error | null;
}
```

- `resource` and `id` fall back to the resource and record contexts, so a call
  inside `<Edit>` or `<Show>` needs neither.
- `identity` falls back to the auth provider's identity.
- With no resource, or no id from either source, it takes no lock and reports no
  error.

## Returns

`lock` is the `Lock` while the session holds it, and `null` before it has one
and after it releases. `isLocking` is true while the lock request is in flight.
`lockError` is the last lock or release that failed, also passed to
`onLockError`.

Changing the data provider, resource, id or identity releases the old lock, even
one still in flight, before the next is taken, so a provider never sees the new
lock ahead of the old release. A new `meta` object, a new `authProvider` or a
new `onLockError` does not relock: the session reads them as they were when it
was made.

The hook throws when the data provider is not a realtime one with lock support
and a resource and id are present. With no `identity` and no auth provider to
read one from, the lock fails with an error saying no identity is available,
which lands in `lockError`.

## Example

```tsx
import { useLockOnMount } from "@chelone/react";

export const PostEditor = ({ id }: { id: number }) => {
  const { lock, isLocking, lockError } = useLockOnMount({
    resource: "posts",
    id,
    identity: "you",
    onLockError: (error) => console.error(error.message),
  });

  if (isLocking) return <p>Requesting the lock…</p>;
  if (lockError) return <p>{lockError.message}</p>;
  if (!lock) return <p>Held by another identity.</p>;
  return <p>Editing as {lock.identity}</p>;
};
```

## In Vue

`@chelone/vue` exports the same name. `resource`, `id` and `identity` take
`MaybeRefOrGetter`, and a change releases the old lock and takes the next.
`lock`, `isLocking` and `lockError` are refs. With no identity to lock for, and
no auth provider to read one from, it takes nothing rather than throwing.

See the [realtime guide](/docs/app-config/realtime) for provider setup, the
`LockProvider` contract and `<LockOnMount>`.
