The `<Create>` view lets users add a new record. Like `<Edit>`, it publishes a
form context and takes inputs directly as children — but it starts from an
**empty** record instead of fetching one, and persists via the data provider's
`create`. A successful save shows a "created" notification and redirects to the
new record's edit page.

## A live create form

<ComponentPreview name="page-components/create/basic" />

```tsx title="src/posts.tsx"
import {
  BooleanInput,
  Create,
  NumberInput,
  ReferenceInput,
  SaveButton,
  SelectInput,
  TextInput,
} from "@chelone/react";

export function PostCreate() {
  return (
    <Create>
      <TextInput source="title" />
      <TextInput source="body" multiline />
      <ReferenceInput source="author_id" reference="authors">
        <SelectInput optionText="name" />
      </ReferenceInput>
      <NumberInput source="views" min={0} defaultValue={0} />
      <BooleanInput source="published" defaultValue={false} />
      <SaveButton />
    </Create>
  );
}
```

Wire it onto the resource so `/posts/create` renders it:

```tsx
<Resource name="posts" create={PostCreate} />
```

## Seeding defaults

Give an input a `defaultValue` to pre-fill it, or seed the whole record with the
`record` prop — handy for pre-populating a create form from a query string or a
parent record:

```tsx
import { Create, SaveButton, TextInput } from "@chelone/react";

<Create record={{ author_id: 1, published: false }}>
  <TextInput source="title" />
  <SaveButton />
</Create>;
```

## Validation from the schema

`<Create>` validates against the resource's Zod schema (registered with
`defineResources`) on submit, exactly as `<Edit>` does. In the preview above, submitting with an empty **Title** surfaces
the schema's required-field message — no per-input `validate` props needed.

## Tips

- `<Create>` has no record id — it starts empty (or from the `record` seed) and
  calls the data provider's `create` on save, then redirects to the new record's
  edit page.
- `<Create>` is pessimistic only: the cache is invalidated and refetched after
  the server answers, never patched ahead of it. See
  [Mutation modes](/docs/page-components/edit/data-mutations#mutation-modes).
- Use a bare `<SaveButton>` on create. `<Toolbar>` always renders Delete next to
  Save, and there is nothing to delete yet.
- A `ValidationError` from the data provider lands on the matching inputs, as on
  `<Edit>`.
