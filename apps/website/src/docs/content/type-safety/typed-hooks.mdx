---
title: "Typed Hooks"
description: "What a record type arrives as, and what the hooks return for a registered resource."
---

The data hooks read the app's registered resources directly, so
`useGetList("posts")` is typed with no factory: the name picks the record, and a
name the app never registered is rejected.

In both adapters: `useGetList`, `useGetOne`, `useGetMany`,
`useGetManyAggregate`, `useGetManyReference`, `useCreate`, `useUpdate`,
`useDelete`, `useGetListLive`, `useGetOneLive` and `useGetManyLive`. In Vue
only, since React has no bulk mutation hook yet: `useUpdateMany` and
`useDeleteMany`.

`useRecordContext` and `useListContext` are not named this way: each still takes
the record type its caller writes.

## The name argument

`ResourceNameArg<TResources, TName>` is the resource argument every data hook
takes. `TResources` defaults to `RegisteredResources`, so an app that augments
`Register` needs nothing at the call site; `createCheloneHooks` is for binding a
different map.

```ts twoslash title="src/hooks.ts"
import { defineResources } from "@chelone/core";
import { useGetList } from "@chelone/react";
import { z } from "zod";

const resources = defineResources({
  posts: { schema: z.object({ id: z.number(), title: z.string() }) },
  comments: { schema: z.object({ id: z.number(), body: z.string() }) },
});

declare module "@chelone/core" {
  interface Register {
    resources: typeof resources;
  }
}

// ---cut---
const list = useGetList("posts");
//    ^?

const row = list.data?.data[0];
//    ^?

// A name the caller holds as a `string`, read from context or props, keeps the
// loose arm.
declare const fromContext: string;
const loose = useGetList(fromContext);
//    ^?
```

A literal the map does not have resolves to `never`, so the call site rejects:

```ts twoslash title="src/hooks.ts"
// @errors: 2345
import { defineResources } from "@chelone/core";
import { useGetList } from "@chelone/react";
import { z } from "zod";

const resources = defineResources({
  posts: { schema: z.object({ id: z.number(), title: z.string() }) },
});

declare module "@chelone/core" {
  interface Register {
    resources: typeof resources;
  }
}

// ---cut---
useGetList("psots");
```

## The record argument

`ResourceRecordArg<TResources, TName>` is what a mutation's `params` carry:
`RecordOf` for a registered name, `LooseRecord` for a wide `string`. An undoable
`useUpdate` patches the cache with it, and `undoableUpdateMutators` and
`undoableDeleteMutators` build the `mutate` / `mutateAsync` pair each adapter
swaps in, so the deferred provider call is written once, in core.

```ts twoslash title="src/hooks.ts"
import {
  defineResources,
  type RegisteredResources,
  type ResourceRecordArg,
} from "@chelone/core";
import { useUpdate } from "@chelone/react";
import { z } from "zod";

const resources = defineResources({
  posts: { schema: z.object({ id: z.number(), title: z.string() }) },
});

declare module "@chelone/core" {
  interface Register {
    resources: typeof resources;
  }
}

// ---cut---
type PostPatch = ResourceRecordArg<RegisteredResources, "posts">;
//    ^?

const update = useUpdate("posts", { mutationMode: "undoable" });
update.mutate({ id: 1, data: { title: "new" } });
```

Vue names the same way, wrapped in `MaybeRefOrGetter` so a resource ref or
getter stays reactive.
