A `<Resource>` declares one entity of your admin. Its `name` is the registry key
and the route base (`/<name>/*`), and each view prop (`list`, `edit`, `create`,
`show`) both registers a route and flags the capability that drives menus and
action buttons.

## Declaring resources

```tsx
import { Resource } from "@chelone/react";
import { PostCreate, PostEdit, PostList, PostShow } from "./posts";

<Resource
  name="posts"
  list={PostList}
  edit={PostEdit}
  create={PostCreate}
  show={PostShow}
/>;
```

This registers four routes — `/posts`, `/posts/create`, `/posts/:id`,
`/posts/:id/show` — and tells the sidebar the resource has a list. Because the
resource also has edit and show views, the list rows link to them.

## Point at a Zod schema

The other half of a resource is its **schema**. `<Resource>` has no `schema` prop:
the schema comes from `defineResources`, keyed by the resource name. Hand the
registry to `<Admin resources={…}>`. Because the resource carries a schema, its
Create/Edit forms validate against it automatically — no per-input `validate`
props:

```tsx title="src/resources/index.ts"
import { defineResources } from "@chelone/core";
import { z } from "zod";

export const postSchema = z.object({
  id: z.number().optional(),
  title: z.string().min(1, "Title is required").max(120),
  body: z.string().min(1),
  author_id: z.number({ message: "Pick an author" }),
  published: z.boolean().optional(),
});

export const resources = defineResources({
  posts: { schema: postSchema },
});
```

```tsx title="src/App.tsx"
import { Admin, Resource } from "@chelone/react";
import { dataProvider, queryClient } from "./providers";
import { PostEdit, PostList } from "./posts";
import { resources } from "./resources";

export function App() {
  return (
    <Admin
      dataProvider={dataProvider}
      queryClient={queryClient}
      resources={resources}
    >
      <Resource name="posts" list={PostList} edit={PostEdit} />
    </Admin>
  );
}
```

The schema is the single source of truth: it types the records **and** drives
form validation.

To get List, Edit and Show pages from the same schema, use the
[guessers](/docs/app-config/guessers).

:::note
Pointing at a schema wires up **validation**, not default views. The views are
yours to write (a dozen lines, as in the [quick start](/docs/react/quick-start-guide/setup)),
unless you hand them to the guessers.
:::

## Labels and menus

`recordRepresentation` controls how a record names itself (a field name, a
function, or a node) — used in titles and breadcrumbs. `icon` sets the menu icon,
and `options.group` buckets the resource under a sidebar group.

```tsx
import { Resource } from "@chelone/react";
import { FileText } from "lucide-react";
import { PostList } from "./posts";

<Resource
  name="posts"
  list={PostList}
  icon={FileText}
  recordRepresentation="title"
  options={{ group: "Content" }}
/>
```

## Tips

- A view prop's **presence** sets the capability flag (`list` present → `hasList`);
  override with the explicit `hasList`/`hasCreate`/… props when a view lives
  elsewhere.
- `children` on a `<Resource>` append extra nested routes after the CRUD routes.
